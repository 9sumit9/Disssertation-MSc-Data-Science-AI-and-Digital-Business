\chapter{Methodology}
We have implemeted a quantitative approach for the study of Cross-Dataset Generalization for Network Intrusion Detection Using Supervised and Unsupervised Machine Learning Models. 
The study focuses on the overall performance of the models in detection of 'Attack' from the test datasets by training the models on an entire train dataset. Since the focus of this 
study is to investigate the cross-dataset generalization capabilities of both supervised and unsupervised machine learning models for network intrusion detection, the models will be 
trained entirely on CIC-IDS-2017 dataset and evaluated on unseen CSE-CIC-IDS2018 and UNSW-NB15 datasets.

The concept recognises that datasets are active components of the experiment rather than neutral containers. Existing reviews identify 
considerable variation in the realism, provenance, attack coverage, class balance, and feature construction of public NIDS datasets 
\cite{Ring2019,Thakkar2020,Kenyon2020,Goldschmidt2025,Pinto2025}. Harmonising feature meaning is necessary for cross-dataset transfer, 
but it does not make independently generated distributions identical. Corresponding features may retain different ranges, frequencies, 
and statistical relationships. These remaining differences form part of the generalisation challenge. Transfer direction must be retained 
explicitly because source and target distributions  are not interchangeable. A model trained using CICIDS2017 and tested using UNSW-NB15 
may behave differently from a model trained using UNSW-NB15 and tested using CICIDS2017.

This asymmetry occurs because each source dataset produces a different representation of normal traffic, preprocessing transformation, and 
decision threshold. Both directions must therefore be evaluated for each pair of datasets. Federated unsupervised detection provides a 
possible extensions to the conceptual framework. Learning from multiple decentralized sources could expose detector to more diverse normal 
behaviour without requiring organizations to centralise sensitive network traffic.

\cite{Gourceyraud2025} combined federated learning with unsupervised clustering. This work connects unsupervised learning, privacy, and 
multi-source data. Federated learning is not evaluated in this dissertation, but it remains relevant to future privacy-preserving approaches 
for increasing the diversity of training data.

CIC-IDS-2017 and CSE- CIC-IDS2018 datasets were downloaded from Kaggle. Meanwhile, the UNSW-NB15 dataset was fetched from Canadian Institute for 
Cybersecurity portal by submitting necessary information. We will employ CIC-IDS-2017 as the train dataset, while CSE- CIC-IDS2018 and UNSW-NB15 
will be our test datasets for cross-dataset generalization for NIDS. A quick exploration of these datasets before data pre-processing showed dominant 
presence of ‘Benign’ class in all the datasets. 2273097 (80.3\%) in CIC-IDS-2017, 13484708 (83.06\%) in CSE- CIC-IDS2018 and 3450658 (97.46\%) in UNSW-NB15 
are labeled as ‘Benign’ indicating huge class imbalance between the benign and attack classes.

\subsubsection{CIC-IDS-2017}
The dataset consists of network traffics collected from Monday to Friday at different time intervals originally extracted by the Canadian 
Institute for Cybersecurity for the study of network intrusion detection. CIC-IDS-2017 datasets were generated utilizing CICFlowMeter to 
create network flows and labelled them according to timestamps, source and target IP address, source and target ports, communication protocol 
and attack types. To prepare a realistic background traffic, Canadian Institute for Cybersecurity (CIC) applied the suggested B-Profile system \cite{Sharafaldin2018} 
to model the abstract patterns of human interactions and generate the realistic benign background traffic from 25 real users. 
The 8 files combined has 79 features and 2830743 rows.

\subsubsection{CSE-CIC-IDS2018}
Among all the datasets used for our research, this one is the biggest in size (10 files of 6.89 GB) with more than 16 million rows and 
84 feature downloaded through Kaggle. CSE-CIC-IDS2018 was a collaborative initiative between CIC and Communications Security Establishment 
(CSE) with the objective of creating standard benchmark datasets for intrusion detection systems to properly detect network anomalies. 
The dataset was generated based on different attack types such as Botnets, Brute force, DoS and Heartbleed by accessing different user 
profiles. The dataset is comprised of 80 features obtained through incoming network traffic and system logs with CICFlowMeter-V3 tool with 
proper utilization of B-profile and M-profile to identify the statistical user behavior through the reproduction of network traffics and 
attack scenarios. The initiative used Slowloris and LOIC to inject HTTP DoS attacks, HOIC for DDoS, and bombarded web applications with 
Damn Vulnerability Web App (DVWA) to test the vulnerabilities.


\subsubsection{UNSW-NB15}

CIC-UNSW-NB15 or simply UNSW-NB15 augmented dataset was created with the help of IXIA PerfectStorm with up-to-date normal and abnormal 
network traffic. The dataset contains 9 types of attacks which the CIC-IDS-2017 and CSE- CIC-IDS2018 datasets lack. CICFlowmeter extracted 
new features from the network flow. The attacks in UNSW-NB15 are categorized by matching the flow records: source/destination IP, port, and 
protocols with the records from ground truth file. UNSW-NB15 prioritized matching Timestamp in-case of multiple records, removed flows that 
could not be categorized and categorized the remaining traffic as benign after malicious flows were processed.

\subsection{Data Pre-Processing}
The first step in data-processing is standardizing all the labels across the datasets. We mapped the labels of the datasets taking reference to 
CSE-CIC-IDS2018. We handled the infinite values in these datasets by replacing them with NaN values. Removing duplicates earlier would significantly 
reduce the size of the datasets, seeing the skewness of the datasets, we replaced the NaN values with the median values from the respective labels. 
And, only after replacing the NaN values with median values, we removed the duplicated values from the datasets. Finally, for the next step we took 
all the common labels from the datasets. We also checked and deleted the bad rows from the datasests.

\subsection{Model Training}
\subsubsection{Random Forest}
Random Forest is a robust ensemble learning model that creates many decision trees and carries out classification by taking the mode of the 
predictions of individual trees. During the training phase, only a random subset of features is considered at each node split. The trees in 
a random forest use a bootstrap-sampled version of the training data to introduce randomness in both the sampling process and feature selection, 
thereby minimizing correlation among the trees and reducing the variance of the ensemble without increasing bias.

The significance of tree-based models lies in their ability to classify the feature space using threshold splits without being affected by 
monotonic transformations of the input features. In this study, we trained Random Forest on the full CIC-IDS-2017 dataset without scaling, 
despite the substantial class imbalance. As Random Forest is resistant to overfitting on high-dimensional flow-related data and shows robustness 
to noisy features, the workflow avoids Synthetic Minority Over-Sampling Technique (SMOTE) and instead uses class weight = "balanced" to 
handle class imbalance. \par

\subsubsection{XGBoost}
eXtreme Gradient Boosting generally termed as XGBoost is a scalable gradient boosting decision tree which boost weak learners. XGBoost utilizes the technique 
where each tree is trained to rectify the mistakes of previous trees. It does not build trees based on parallel bagging as Random Forest does. Rather XGBoost 
allows trees to grow in additive way to optimize the differential loss function using gradient descent. It employs L1 and L2 regularization to control overfitting 
and complexity. XGBoost inhibits computational effectiveness and robustness in solving structured data and is capable to construct parallel tree to deal with the 
missing data.

So, with its exceptional ensemble technique to compare methods of ensemble trees that differ in aggregation approach (sequential vs parallel), 
we have selected XGBoost along with Random Forest as our benchmark supervised learning models. Like random forest, we have implemented 
class-weighing to mitigate the class imbalance between the benign and malicious cases in the training set, i.e. CIC-IDS-2017.

\subsubsection{Deep Neural Network (DNN)}
DNN learn feature interactions without manual feature extraction giving it an extra edge over tree-based ensemble techniques. 
DNN is dependent on the size/amount of data, thus shows better performance as the degree of changes in inputs rises. DNN uses 
hidden layers for classification. Each hidden layer utilizes ReLU activation to bring in non-linearity after each hidden layer 
to prevent the vanishing gradient problem of deeper models.

To avoid memory crash given the size of the dataset, we tested on 20\% of the CIC-IDS-2017 with tuning size of 300000.Considering the computational cost 
and to prevent memory crash, we have assigned n\_trials to 30 only. We have implemented 4 hidden layers with 512, 256, 128 and 64 neurons for binary 
classification “benign” and “attack”  in this study. We have implemented RobustScaler for scaling the datasets to mitigate the effect of strong outliers 
(flow duration, packet inter-arrival times). Similar to Random Forest and XGBoost which utilizes class-weight, weighted loss in DNN handles class imbalance. 
In consideration to the huge test dataset size, prediction and evaluation of the model has been performed in batches of max 4096. The best\_dnn\_params 
identifies the best configuration of the model specifically the number of layers, units per layer, dropout rate and the learning rate to construct the best 
DNN architecture. Thus, the evaluation using DNN architecture works in two phases, first finding the best configuration by training and testing the model 
on CIC-IDS-2017 and secondly using the best hyperparameters to evaluate the performance of the model on the test datasets CSE-CIC-IDS2018 and UNSW-NB15.

\section{Cross-Dataset Generalization using Unsupervised Machine Learning Models}
The following workflow proposes that anomaly-detection performance is influenced by the selected model, evaluation setting, source dataset, 
target dataset, and direction of transfer. Dataset shift moderates these relationships because differences between source and target traffic 
alter the distributions of the features used by the detector.

Isolation Forest, One-Class SVM, and the improved autoencoder represent normal traffic differently. Isolation Forest measures how easily 
observations can be isolated. One-Class SVM estimates a boundary around normal traffic. The improved autoencoder measures reconstruction error. 
Evaluation setting plays significant role in the performance of models for intrusion detection. Within-dataset evaluation tests a model 
using held-out observations originating from the same dataset as the training data. Cross-dataset evaluation applies a source-fitted model 
to independently collected target traffic.

The relationships are controlled through a harmonised features space, source-only preprocessing, consistent data partitions, source-validation 
calibration, common metric definitions, and the prohibition of target-domain training or threshold calibration.

 For a source dataset \(D_s\), a detector learns an anomaly-scoring functions \(f_s(x)\). A source -validations procedures selects an operating threshold \(\tau_s\).  \subsection {Stratified Data Partitioning}
 
 Each dataset was divided using stratified random partitioning so that the proportions of benign and attack observations were approximately preserved.
 
 First, 20\% of each dataset was reserved as the final test partitions. The remaining 80\% formed the development partition 
 
 Second, 20\% of the development partition was reserved for validation. Before sample caps were applied, the effective allocation was therefore approximately;
 
\begin{itemize}
        \item 64\% training pool
        \item 16\% validation partition
        \item 20\% final test partition
\end{itemize}
 
 Only benign observation from the training pool was retained for model fitting. Both benign and attack observation were retained in the source-validation and final test partitions.
 
 The validation partition was used for source -domain model selection and threshold calibration. The partition remained independent of model development and was used only for final evaluation.
 
 \subsection{Bounded Sampling}
 
 Computationally bounded samples were used to maintain feasible and consistent experiments. The following maximum sample sizes were defined:
 
 \begin{itemize}
        \item normal training data: 100,000 observations
        \item validation data: 50,000 observations
        \item final test data: 80,000 observation
        \item One-Class SVM training data: 8,000 normal observation
 \end{itemize}
 
 When a validation or test partition exceeded its corresponding cap, stratified sampling was used to retain approximately the same class distribution.
 
 Normal-Training and One-Class SVM samples were selected without replacement using seeded random sampling. These caps were introduced as  computational controls and did not permit observations to be shared across training, validation, and testing partitions.
 
 \subsection{Autoencoder Validation Sample}
 
 Normal observations from the source-validation partition were identified and shuffled using seeded random generator. A held out portion of those normal observation was used to monitor reconstruction loss and apply early stopping.
 
 The complete labelled source-validation partition was used separately to calculate anomaly scores and select the final decision threshold.

\subsection{Model Training}
\subsubsection{Isolation Forest}
\label{subsec:isolation-forest}

Isolation Forest is a tree-based anomaly detectors that recursively partitions the features space using randomly selected features and spit values. Rare or structurally unusual observations tend to be isolated using shorter tree paths than observations located in dense regions.

An ensemble of isolation trees converts the average path length into an anomaly score. Shorter average paths indicates a greater degree of anomaly.

The methods is suitable for tubular network-flow data because it is scalable and does not require pairwise distance calculations between all observations. Random subsampling also reduces its computational requirements.

\begin{equation}
       s(x, n) =
       2^{-\frac{E[h(x)]}{c(n)}},
       \label{eq:isolation-score}
\end{equation}

where  \(E[h(x)]\) is the expected path length of \(x\)  across the isolation trees and \(c(n)\) is the normalizing path length for a sample containing \(n\)  observations.  Values closer to one indicate stronger anomalies.

However, the method's definitions of isolation depends on the distribution learned from the source data. Legitimate target observation may be isolated quickly when their feature values fall outside the ranges observed in the source dataset. 
Isolation Forest may therefore achieve high recall while generating a large number of false positives under severe distribution shift. Accuracy alone cannot reveal this trade-off. Precision, recall, F1\_Score, and false-positive rate must therefore be interpreted together \cite{Verkerken2022, Yang2022}.

Isolation Forest implementation:
\begin{itemize}
       \item 350 isolation trees;
       \item automatic contamination estimation;
       \item parallel processing;
       \item a fixed base random state of 42; and
       \item three candidate maximum-sample values.
\end{itemize}

The candidate maximum-sample values were:

\begin{equation}
       m \in \{512, 2048, 8192\}.
       \label{eq:if-sample-candidates}
\end{equation}

When a candidate exceeded the available number of normal-training observations, the complete available sample was used.

Each candidate was fitted using normal source traffic. Its anomaly scores were calculated for the labelled source-validation partition. The candidate producing highest source-validation F1-score was selected.

The decision function was inverted so that larger scores represented stronger anomalies:

\begin{equation}
       s_i^{IF} =
       -f_{\mathrm{decision}}(x_i).
       \label{eq:if-anomaly-score}
\end{equation}

The selected Isolation Forest model and its source-calibrated threshold were frozen within-dataset and cross-dataset testing.


\subsubsection{One-Class Support Vector Machine }
\label{subsec:one-class-svm}

One-Class SVM is a boundary-based anomaly detector. It maps normal training observations into a transformed features space using a kernel functions and estimates a boundary containing most of those observations.

The model attempts to separate the transformed normal observations from the origin with the greatest possible margin. A simplified objective functions is expressed as: 
\begin{equation}
       \min_{w, \rho, \xi}
       \left[
            \frac{1}{2}\Vert w\rVert^2
            +
            \frac{1}{\nu n}
            \sum_{i=1}^{n}\xi_i
            -
            \rho
       \right],
       \label{eq:ocsvm-objective}
\end{equation}

subject to:

\begin{equation}
       w^{T}\phi(x_i) \geq \rho-\xi_i,
       \qquad
       \xi_i \geq 0,
       \label{eq:ocsvm-constraints}
\end{equation}


where \(\phi(x_i)\) maps observation \(x_i\) into the kernel feature space, \(\rho\) determine the decision boundary, \(\xi_i\) represents a slack variable,  and \(\nu\) controls the permitted proportion of training observation outside the estimated boundary.

The radial basis functions kernel allows the model to represent a non-linear normal-traffic boundary. It is expressed as:

\begin{equation}
       K(x_i, x_j) =
       \exp\left(
               -\gamma\lVert x_i-x_j\rVert^2
        \right),
        \label{eq:rbf-kernel}
\end{equation}

where \(\gamma\) controls the influence of individual training observations.

The model's behavior is influenced by feature scaling, \(\gamma\), \(\nu\),  and the size of the training sample. One-Class SVM is therefore sensitive to preprocessing decisions and hyperparameter selection.

A boundary fitted tightly around the source distribution may reject large amount of legitimate target traffic. Conversely, an overly broad boundary may accept malicious observations. Its computational and memory requirements may also increase substantially as the training sample grows \cite{Verkerken2022,Khraisat2019}.

One Class SVM was fitted using a maximum of 8,000 randomly selected normal source observations. Bounding the training sample reduced the computational and memory requirements of kernel model.

A radial basis function kernel was employed. Two candidate configurations were evaluated:

\begin{itemize}

\item \(\nu=0.03\) with \(\gamma=\texttt{scale}\); and
\item \(\nu=0.08\) with \(\gamma=0.05\).
\end{itemize}

Each candidate was fitted using the same bounded normal source sample and evaluated using the source-validation partition. The configuration producing the highest validation F1\_Score was selected.
The decision function was inverted so that the larger values represented stronger anomalies.
\begin{equation}
       s_i^{\mathrm{SVM}} = 
       -f_{\mathrm{decision}}(x_i).
       \label{eq:svm-anomaly-score}
\end{equation}

The selected model and source-calibrated threshold were applied unchanged to every target dataset associated with the source domain. 

\subsubsection{Improved Autoencoder}
\label{subsec:improved-autoencoder}

An autoencoder consists of an encoder and a decoder. The encoder maps an input observations to lower-dimensional latent representation:

\begin{equation}
       z_i = f_{\theta}(x_i),
       \label{eq:encoder}
\end{equation}

where \(x_i\) is the input observation, \(z_i\) is its latent representation, and \(\theta\) represents the encoder parameters.

The decoder attempts to reconstruct the original input:

\begin{equation}
      \hat{x}_i = g_{\phi}(z_i),
      \label{eq:decoder}
\end{equation}

where \(\phi\) represents the decoder parameters.
When the autoencoder is fitted using normal traffic, it is expected to reconstruct observation resembling the training data more accurately than anomalous observations.

For an observations \(x_i\) and its reconstruction \(\hat{x}_i\), the mean-squared reconstruction error is:

\begin{equation}
      s_i^{AE} =
      \frac{1}{d}
      \sum_{j=1}^{d}
      \left(x_{ij}-\hat{x}_{ij}\right)^2,
      \label{eq:ae-score}
\end{equation}

where \(d\) is the number of input features. A higher reconstruction error indicates a greater departure from the learned representation of normal traffic.

Deep representation learning support the modeling of non-linear relationships that may be difficult for shallow methods to represent. However, additional model capacity does not automatically improve anomaly detection. A highly expressive decoder may reconstruct attack observation accurately, while an overfitted latent representation may encode pattern specific to the source dataset. 
Regularization architecture selection, validation and early stopping are therefore important \cite{Pang2021,Yang2022}. The improved autoencoder used in the present study employs a deeper regularized architecture and early stopping to reduce overfitting.

These improvement do not eliminate distribution shift. Normal target traffic may still produce large reconstruction error when its patterns differ substantially from the source-domain data. 
The improved auto encoder was implemented using PyTorch. For input dimension \(d\), the hidden -layer size was defined as:

\begin{equation}
       h= \max(16,2d),
       \label{eq:ae-hidden-size}
\end{equation}

and the bottleneck dimension was defined as :

\begin{equation}
       b= \max\left(
                    4,
                    \left\lfloor\frac{d}{2}\right\rfloor
       \right).
       \label{eq:ae-bottleneck-size}
\end{equation}

because the experiment used nine input features, the resulting architecture was: 

\begin{equation}
       9 \rightarrow 18 \rightarrow 4
       \rightarrow 18 \rightarrow 9.
       \label{eq:ae-architecture}
\end{equation}

The encoder applied a linear layer, batch normalization, Leaky ReLU activation, five-per-cent dropout, and a second linear layer leading to the bottleneck. The decoder reconstructed the input through a hidden layer and output layer.

The model was optimized using AdamW with:

\begin{itemize}
       \item learning rate  \(8\times10^{-4}\);
       \item weight decay \(1\times10^{-5}\);
       \item training batch size of 1,024;
       \item maximum of 25 epochs; and
       \item early-stopping patience of six epochs.
\end{itemize}

Smooth L1 loss was used for training because it is less sensitive to extreme reconstruction errors than ordinary mean-squared  loss.
Early stopping monitored reconstruction loss using held out normal source-validation observations. The model parameters producing the lowest validation loss were restored after training.

The final anomaly score was the mean-squared reconstruction error:

\begin{equation}
       s_i^{AE} =
       \frac{1}{d}
       \sum_{j=1}^{d}
       \left(x_{ij}-\hat{x}_{ij}\right)^2.
\label{eq:method-ae-score}
\end{equation}

A higher reconstruction error indicated a greater departure from the normal source-domain representation.

\subsection{Threshold Calibration}
\label{subsec:method-threshold-calibration}

Each model produced a continuous anomaly score. A threshold was required to convert that score into a binary prediction:

\begin{equation}
       \hat{y}_i = 
       \begin{cases}
             1, & \text{if} s_i \geq \tau_s, \\
             0, & \text{if} s_i < \tau_s.
       \end {cases}
       \label{eq:method-decision-rule}
\end{equation}

The threshold producing the highest source-validation F1\_Score was selected:


\begin{equation}
       \tau_s = 
       \arg\max_{\tau}
       F1\left(
                y_s^{\mathrm{val}},
                \mathbb{I}
                \left[
                    s_s^{\mathrm{val}}\geq\tau
                \right]
        \right).
        \label{eq:threshold-selection}
\end{equation}

The selected source threshold was frozen before testing. Target labels were not used to select, modify, or recalibrate it.

F1\_Score measured the quality of binary predictions produces by the source calibrated threshold. ROC--AUC measured the ability of the continuous scores to rank attack observations above benign observations across possible thresholds.

Performance deterioration was calculated by comparing a cross-dataset result with the corresponding source model's within-dataset baseline:

\begin{equation}
       \mathrm{Deterioration} =
       \frac{
            M_{\mathrm{within}}-M_{\mathrm{cross}}
        }{
            M_{\mathrm{within}}
        }
        \times100, 
        \label{eq:method-deterioration}
\end{equation}

where \(M\) represents F1\_Score or ROC--AUC. A positive value indicated performance deterioration during cross-dataset transfer, whereas a negative value indicated that cross-dataset performance exceeded the corresponding within-dataset baseline.

\subsection{Model Evaluation}
Since, the main objective of the study is to find out which model shows robust performance in cross-dataset generalization for network intrusion detection,
we have prioritized F1-Score, MCC and ROC-AUC Curve as the evaluation metrics. Accuracy alone cannot define whether the model performed better in detecting 
'Attack' from the  network traffic. 
\begin{itemize}
    \item {Precision:} It gives the measure of the proportion that are predicted as Positive. It is the ratio of True Positives (TP) to the summation of 
    True Positives and False Positives (FP).  
\end{itemize}
\[
\text{Precision} = \frac{TP}{TP+FP}
\]
\begin{itemize}
    \item Recall: Unlike Precision, it gives the measure of positives that are correctly predicted as Positive. It demonstrates the model's proficiency in detecting
    True Positives while limiting False Negatives (FN). It is the ratio of True Positives (TP) to the summation of True Positives and False Negatives (FN).
\end{itemize}
\[
\text{Recall} = \frac{TP}{TP+FN}
\]
\begin{itemize}
    \item {F1\_Score:} It is the harmonic mean of Precision and Recall giving a balanced measure that shows the overall performance of the model minimizing both 
    False Positives and False Negatives.
\end{itemize}
\[
\text{F1\_Score} = 2 \times \frac{\text{Precision} \times \text{Recall}}
{\text{Precision} + \text{Recall}}
\]
\begin{itemize}
    \item {MCC:} Matthews Correlation Coefficient or simply MCC is a metric used to evaluate the classification performance of the model by determining the correlation between
    actual and predicted classes, preferrable metric for evaluating model performance on imbalanced datasets. Its value ranges from -1 to 1; 1 indicates strong prediction, 0 
    indicates random prediction and -1 represents weak prediction between actual and predicted classes.
\end{itemize}
\[
\text{MCC} = \frac{TP \times TN - FP \times FN}
{\sqrt{(TP+FP)(TP+FN)(TN+FP)(TN+FN)}}
\]
\begin{itemize}
    \item {ROC-AUC:} Receiver Operating Characteristic Area Under Curve (ROC-AUC) gives the measure specifying how well the model performed in distinguishing the positive 
    and negative classes into correct labels with respect to various classification thresholds. The value ranges from 0 to 1; higher the value better the classification of 
    the classes. 
\end{itemize}
\[
\text{ROC-AUC} = \int_{0}^{1} \mathrm{TPR}(\mathrm{FPR}) \, d(\mathrm{FPR})
\]
